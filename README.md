# DCURS Website — Version 5 (Deployment Ready)

This version adds deployment configuration for Render:
- Dockerfile
- render.yaml Blueprint
- persistent SQLite disk at `/var/data`
- `/health` health-check endpoint
- production environment variables
- `.dockerignore`

## Recommended deployment flow

1. Create a GitHub repository and upload this project.
2. In Render, choose **New → Blueprint** and connect the GitHub repository.
3. Render reads `render.yaml`.
4. Set `ADMIN_USERNAME` and a strong `ADMIN_PASSWORD` when prompted.
5. `SESSION_SECRET` is generated by Render.
6. Deploy the service.
7. Test `/health`, the homepage, `/join.html`, and `/admin.html`.
8. Add the official custom domain in Render and configure DNS.

### Important
The SQLite database is stored on a Render persistent disk. Render documents that persistent disks preserve filesystem data across deploys/restarts, but they are available only to one service instance and require a paid service. For a larger organization or multi-instance scaling, migrate the database to managed Postgres instead.

Never publish the admin password or SESSION_SECRET in GitHub.

For production, also add rate limiting, stronger identity management/password hashing, audit logs, backups, email verification, and role-based permissions.

## Local run

Node.js 20+:
- `npm install`
- set environment variables
- `npm start`
- open `http://localhost:3000`
